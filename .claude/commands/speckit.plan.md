You are creating an implementation plan for a feature specification.

## Prerequisites
- Identify the current feature: find the most recent `specs/NNN-*/spec.md` or read the active git branch name
- Read the spec: `specs/NNN-feature/spec.md`
- Read `.specify/memory/constitution.md` for architectural constraints
- Read `.specify/templates/plan-template.md` for plan structure (or `.specify/overrides/plan-template.md` if it exists)
- Read `.specify/templates/research-template.md` for research format
- Read `.specify/templates/data-model-template.md` for data model format

## Your task
Create a complete technical implementation plan across three phases:

### Phase 0: Research
1. Investigate libraries, frameworks, and approaches needed for this feature
2. For each key technical decision, compare ≥2 options with pros/cons
3. Verify chosen options comply with constitution (Articles I, III, VII, VIII)
4. Document findings in `specs/NNN-feature/research.md` using the research template

### Phase 1: Design
1. **Constitution gates check** — document results in plan.md under "Constitution Check":
   - Simplicity Gate: ≤3 services? No future-proofing? No speculative abstractions?
   - Anti-Abstraction Gate: Using framework directly? Single model per entity?
2. **Data model** — define entities, fields, relationships, constraints → `specs/NNN-feature/data-model.md`
3. **API/event contracts** — define all endpoints, request/response shapes, error codes → `specs/NNN-feature/contracts/api.md`
4. **Implementation plan** → `specs/NNN-feature/plan.md` using plan-template.md:
   - Fill in Technical Context (language, deps, storage, testing, platform, performance, scale)
   - Fill in Project Structure (choose Option 1/2/3 and justify)
   - Fill in Implementation Phases 0, 1, 2
   - Document any constitution violations in Complexity Tracking

### Phase 2: Prepare Tasks (note only)
- Do NOT create tasks.md here — it is generated by `/speckit:tasks`
- Note in plan.md: "Run `/speckit:tasks` to generate the task list"

## Constitution Gates (MUST CHECK before writing plan)
**Simplicity Gate**:
- [ ] Using ≤3 projects/services?
- [ ] No code for requirements outside the current spec?
- [ ] No interfaces/abstractions with <2 concrete implementations?

**Anti-Abstraction Gate**:
- [ ] Using framework primitives directly (no wrapper layers)?
- [ ] Each entity has exactly one model representation?

If any gate fails, document the violation in the Complexity Tracking section and either redesign or get explicit approval.

## Output
- List of files created (research.md, data-model.md, contracts/api.md, plan.md)
- Summary of key architecture decisions (3–5 bullet points)
- Constitution gate pass/fail status
- Next command to run: `/speckit:tasks`
